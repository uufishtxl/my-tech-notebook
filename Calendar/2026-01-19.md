## 方法：`loadSessionInfo`

1. 获取当前活跃的浏览器活跃的 `tab` (`chrome.tabs.query(options)`)。
2. 通过 `sendToContent`发送消息到 `content script`。
   这里会用 Promise 重新封装 chome 提供的 `chrome.tabs.sendMessage(tabId, message, (response) => {})`方法为一个 `Promise`。这个原生 API 的参数：
	- `tabId`：**目标标签页的 ID**。Chrome 给每个打开的 Tab 都分配一个唯一数字。消息会发送到这个 Tab 里正在运行的 Content Script。
	- `message`：**消息内容**。可以是任意可序列化的数据（对象、字符串、数组等）。通常用对象 `{ action: 'xxx', data: ... }` 来区分不同类型的请求。
	- `callback`：**回调函数**（可选）。当 Content Script 调用 `sendResponse(data)` 后，Chrome 会把 `data` 传给这个回调函数。

我问 Claude 这是各个 Chat GPT 约定成俗的惯例吗？

Claude 的回答如下：
> 不是行业标准，只是各家的实现碰巧相似。每个 AI 产品的 DOM 结构都不同：

| 产品      | AI 回复容器 Class（大致）          |
| ------- | -------------------------- |
| Gemini  | `.markdown`                |
| ChatGPT | `markdown-body` 或 `.prose` |
| Claude  | 类似结构但 `class` 名不同          |
之所以都叫 `markdown` 相关的名字，是因为 AI 回复本质上都是 Markdown 渲染成 HTML，用这个 class 来标识“这块内容是渲染后的 Markdown”是合理的命名习惯，但不是标准协议。

在 `turndown.js` 转换 turn EL 后，有以下代码：
```JavaScript
answer = rawMd
          .replace(/\\\[\\\[/g, '[[')
          .replace(/\\\]\\\]/g, ']]');
```
这是因为：
- 在 Obsidian 里，双方括号表示内部链接，可以链接到笔记库中的其他笔记。
- Turndown在转换时，会把 `[[` 和 `]]`当做可能干扰 Markdown 的特殊字符而转义。
- 为了让 Obsidian 能够识别为链接，要进行还原。
