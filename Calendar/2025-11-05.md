## 创建 GET API 的三个关键步骤

1. Serializers：将 Model 转换为 JSON。
2. APIView：创建 API，处理 GET 请求，返回数据。
3. 将 API 注册到路由。

### Serializers

* 是什么
* `serializer = PhraseLogSerializer(logs, many=True)` 中的 `many`参数
	这是 Django REST Framework 中的特性，`many=True` 是在告诉 serializer 正在 serialize 一个列表（QuerySet），而不是一个单一项。
	* 如果 `many=False`就表示，serializer期望的是一个单一的 Model 实例。
	* 反之，则期望一个 Model 实例组成的列表或 QuerySet。

### 大量数据行

返回的数据数量大时，需要使用 Paginattion 作为策略。这需要前后端共同处理。

* 后端：执行分页。一次不能发送所有数据。而应该在每次请求时，将数据分成更小数量的“页”来进行发送。API 响应中也需要包含包括数据总行数、总页数、以及前往前后页链接这样的元数据。
* 前端：“消化”分页API。一开始请求第一页，然后提供 UI 控件来协助用户前往特定的页面。

如何执行

Django Framework 内置了一套强大好用的分页系统。最佳实践是，从一个泛型的 APIView 转换 HistoryAPIView为ListAPIView，从而集成分页功能。

需要执行两个步骤：
* 在 settings.py 中配置默认分页设置
	```Python
	REST_FRAMEWORK = {

    # 默认的认证方式：我们使用 JWT

    'DEFAULT_AUTHENTICATION_CLASSES': (

        'rest_framework_simplejwt.authentication.JWTAuthentication',

    ),

    # 默认的权限：默认情况下，所有 API 都必须是已登录用户才能访问

    'DEFAULT_PERMISSION_CLASSES': (

        'rest_framework.permissions.IsAuthenticated',

    ),

    # --- 新增分页配置 ---

    'DEFAULT_PAGINATION_CLASS': 'rest_framework.pagination.PageNumberPagination',

    'PAGE_SIZE': 10, # 每页显示 10 条记录

}
	```
* 修改 HistoryAPIView，集成 ListAPIView。
	```Python
	from rest_framework.generics import ListAPIView # 导入 ListAPIView
	class HistoryAPIView(ListAPIView): # Inherit from ListAPIView
    """
    处理“获取历史记录”的 GET 请求 (V1.01 功能)。
    """
    # --- 【Task 2】 (保护这个 API) ---
    permission_classes = [IsAuthenticated]
    serializer_class = PhraseLogSerializer # Specify the serializer
    def get_queryset(self):
        """
        This view should return a list of all the phrase logs
        for the currently authenticated user.
        """
        return PhraseLog.objects.filter(user=self.request.user).order_by('-created_at')
	```
	> [!Tip]
	> `-created_at`: 在字段名前面加上一个减号 (`-`) 表示按照 `created_at` 降序排列。

> [!Tip]
> 需要注意的是，ListAPIView是一个自动挡，或者语法糖？只要告诉要序列化什么数据、以及从哪儿获取即可。当然，在这背后，其实有一系列的操作：1）执行 `get_query()`方法获取列表；2）获取 serializer class；3）看到数据是一个queryset，所以会自动添加 `many=True`，4）还会自动处理分页。
> 而APIView则是一个基础的、“手动档”的的“车”。你可以完全控制自己要做什么，是要数据呢，还是手动实例化一个 serializer；如果需要一个列表或者 queryset，则必须通过 many=True 告知它。

```Python
class TagAPIView(APIView):
    """
    处理“获取所有标签”的 GET 请求。
    """
    permission_classes = [IsAuthenticated]
    def get(self, request):
        # 只获取当前用户的标签
        tags = Tag.objects.filter(user=request.user).order_by('name') # 1. 获取数据
        serializer = TagSerializer(tags, many=True) # 2 序列化，并且说明是列表
        return Response(serializer.data, status=status.HTTP_200_OK) # 返回JSON数据和响应状态
```

## PATCH
### 和 PUT 的区别

* PUT：直接替换掉目标资源；必须包含所有字段
* PATCH：修改资源；只包含需要修改的字段

步骤：
* 检查query params是否存在
* 检查是否符合 query params 的参数
* 利用 Serializer，传入
	* 原来的数据
	* request.data
	* 是否部分修改（布尔值）
	即可完成。

## Gneric `RetrieveUpdateDestroyAPIView`

Django Rest Framework 的一个泛型 APIView。只要继承自它的 View的实例，就会自带 GET、PUT、PATCH、DELETE 功能。只要告诉我们的 View 两件事情：1）如何序列化数据 2）要处理什么数据

参数不再以 query 的形式出现，而直接这样使用：`/api/logs/<id>`
