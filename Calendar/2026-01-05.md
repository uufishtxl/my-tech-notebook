## Task 的解析

DITA 的 XML 会提供一种强约束机制。可以试着从报错信息勘破一二：

```
((note|hazardstatement)*, cmd, (choices|choicetable|info|itemgroup|stepxmp|substeps|tutorialinfo)*, stepresult?, steptroubleshooting?)
```

用自然语言，可以看到它对 `step` 是一个有序序列，顺序约束是：

`note`/`hazardstatement`（0个或多个）→ `cmd` → `choices`/`choicetable`/`info`/`itemgroup`/`stepxmp`/`substeps`/`tutorialinfo` （0个或多个） → `stepresult` （0个或1个）→ `steptroubleshooting` (0个或1个)

在这个约束中，`cmd`是这个序列的锚点：
 - **之前**：只能放 `<note>` (提示) 或 `<hazardstatement>` (危险警告)。—— _这也符合逻辑：操作前要先看警告。_
 - **之后**：才能放 `<info>` (补充信息)、`<stepresult>` (结果)、`<stepxmp>` (例子)。—— _逻辑：操作后才会有结果。如果把 `info` 放在 `cmd` 前面，不仅机器编译会报错，人类阅读时也会感到时序混乱。这种强约束保证了文档的逻辑严谨性。_
### Task 核心标签速查表

以下是 **DITA Task 类型核心标签速查表**：

| **标签组合 (Tag Pair)**            | **一般包含的内容 (Content)**                                                | **使用场景 (Usage Scenario)**                                                               | **开发者类比 (Dev Analogy)**             |
| ------------------------------ | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | ----------------------------------- |
| `<prereq>`                     | **准备工作**。<br><br>  <br><br>包含工具、环境、安全状态、所需文件等。                       | **任务开始前**必须满足的条件。<br><br>  <br><br>例：“确保已安装 Python 3.8+。”                               | `import` /依赖检查 / `assert`           |
| `<context>`                    | **背景介绍**。<br><br>  <br><br>解释为什么要执行这个任务，或任务的上下文。                     | **任务开始前**的说明。<br><br>  <br><br>例：“使用此命令启动本地服务器以进行调试。”                                   | `docstring` / 函数注释                  |
| `<steps>` / `<step>`           | **步骤容器**。<br><br>  <br><br>包含一系列有序的操作步骤。                             | **核心流程**。整个任务的主体骨架。<br><br>  <br><br>注意：必须包含至少一个 step。                                  | Main Loop / 算法逻辑                    |
| `<note>` / `<hazardstatement>` | **提示或警告**。<br><br>  <br><br>包含 Tips, Note, Caution, Warning, Danger。 | **放在 `<cmd>` 之前**。<br><br>  <br><br>提醒用户注意安全或操作技巧。<br><br>  <br><br>例：“警告：操作前请断开电源。”    | `try...except` / 异常处理 / Log Warning |
| `<cmd>`                        | **核心指令** (必填)。<br><br>  <br><br>包含一个具体的动作动词（祈使句）。                    | **步骤的核心**。<br><br>  <br><br>这是用户真正要做的动作。<br><br>  <br><br>例：“点击**保存**按钮。”               | Executable Statement / `run()`      |
| `<info>`                       | **补充信息**。<br><br>  <br><br>对动作的解释、辅助说明。                              | **放在 `<cmd>` 之后**。<br><br>  <br><br>当一句话说不完，需要额外补充时用。<br><br>  <br><br>例：“此操作可能需要几分钟。”  | `print()` / 注释                      |
| `<stepxmp>`                    | **步骤示例**。<br><br>  <br><br>包含代码块、截图或示例文字。                            | **放在 `<cmd>` 之后**。<br><br>  <br><br>展示具体怎么做，或者给一个范例。<br><br>  <br><br>例：展示一段 Python 代码。 | Example Usage / Demo                |
| `<stepresult>`                 | **预期结果**。<br><br>  <br><br>描述操作后的系统反馈。                               | **放在 `<cmd>` 之后**。<br><br>  <br><br>告诉用户怎么判断这步做对了。<br><br>  <br><br>例：“屏幕显示‘成功’消息。”     | Return Value / Output               |
| `<substeps>` / `<substep>`     | **子步骤**。<br><br>  <br><br>将一个大步骤拆解为更细的小步骤。                           | 当某一步太复杂，需要分 1.1, 1.2 执行时。<br><br>  <br><br>例：“步骤 1：配置网络（包含输入 IP、掩码、网关）。”                | Nested Function / 内部逻辑              |
| `<choices>` / `<choice>`       | **选项列表**。<br><br>  <br><br>用户需要二选一或多选一的情况。                           | 当一步有多种做法时。<br><br>  <br><br>例：“选择安装路径：A. 默认路径；B. 自定义路径。”                                | `switch...case` / `if...else`       |
| `<postreq>`                    | **后续工作**。<br><br>  <br><br>任务完成后要做的事。                                | **任务结束后**的收尾。<br><br>  <br><br>例：“重启机器以使配置生效。”                                          | `finally` / Cleanup / 回调            |

```XMl
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE task PUBLIC "-//OASIS//DTD DITA Task//EN" "task.dtd">
<task id="task_config_db">
    <title>Configuring the Database Connection</title>
    
    <taskbody>
        <prereq>
            <p>Ensure that the database service is installed and running.</p>
        </prereq>
        
        <steps>
            <step>
                <cmd>Select the database engine based on your environment.</cmd>
                <choices>
                    <choice>For <b>Production</b>, select PostgreSQL.</choice>
                    <choice>For <b>Development</b>, select SQLite.</choice>
                </choices>
            </step>
            
            <step>
                <cmd>Edit the <filepath>settings.py</filepath> file to define connection parameters.</cmd>
                <substeps>
                    <substep>
                        <cmd>Set the <parmname>ENGINE</parmname> parameter.</cmd>
                    </substep>
                    <substep>
                        <cmd>Enter the <parmname>NAME</parmname> of your database.</cmd>
                    </substep>
                    <substep>
                        <cmd>Provide the <parmname>USER</parmname> and <parmname>PASSWORD</parmname>.</cmd>
                    </substep>
                </substeps>
            </step>
            
            <step>
                <cmd>Apply the database migrations.</cmd>
                
                <stepxmp>
                    <codeblock outputclass="language-bourne">python manage.py migrate</codeblock>
                </stepxmp>
                
                <stepresult>
                    <p>The system displays the following success message:</p>
                    <msgblock>Operations to perform: Apply all migrations: ... OK</msgblock>
                </stepresult>
            </step>
        </steps>
        
        <postreq>
            <p>Restart the application server to apply the changes.</p>
        </postreq>
        
    </taskbody>
</task>
```


### DITA 中的样式

DITA 的核心理念是：**内容与样式分离**。XML 只有结构，没有任何样式引用。样式是在**构建**阶段注入的。
在 DITA 中，可以用 CSS 同时控制网页版和 PDF 的样式。
文件结构：
```
my_dita_project/
├── maps/
│   └── my_project.ditamap
├── topics/
│   ├── task_install.dita
│   └── ...
├── css/              <-- 新建这个
│   └── custom.css    <-- 在这里写你的样式
```

```css
/* =========================================
   1. 基础排版优化 (Typography)
   ========================================= */
body {
    /* 使用无衬线字体，更现代 */
    font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif;
    color: #333;
    line-height: 1.6;
}

/* =========================================
   2. 行内元素美化 (Inline Elements)
   cmd (指令), filepath (路径), userinput (输入)
   风格：类似 GitHub 的行内代码块，浅灰底，等宽字体
   ========================================= */
*[class~="topic/cmd"],
*[class~="topic/filepath"],
*[class~="topic/userinput"],
*[class~="sw-d/cmdname"] { /* 兼容不同 DITA 插件的类名 */
    font-family: "SFMono-Regular", Consolas, "Liberation Mono", Menlo, monospace !important;
    background-color: #f6f8fa !important; /* GitHub 浅灰 */
    border: 1px solid #d0d7de !important;
    color: #24292f !important;
    padding: 2px 6px !important;
    border-radius: 4px !important;
    font-size: 0.85em !important;
    font-weight: normal !important; /* 去掉粗体，更清爽 */
    box-decoration-break: clone;
}

/* =========================================
   3. 代码块美化 (Codeblock)
   风格：VS Code Dark Theme
   ========================================= */
*[class~="topic/codeblock"], pre {
    background-color: #1e1e1e !important; /* VS Code 深黑背景 */
    color: #d4d4d4 !important;            /* 柔和的白色文字 */
    font-family: "Fira Code", Consolas, monospace !important;
    border: none !important;
    border-radius: 6px !important;
    padding: 16px !important;
    margin: 1em 0 !important;
    overflow-x: auto !important; /* 横向滚动条 */
    line-height: 1.5 !important;
    box-shadow: 0 4px 6px rgba(0, 0, 0, 0.1);
}

/* =========================================
   4. 警告框美化 (Admonitions/Notes)
   风格：现代 UI 的 Alert 组件 (左侧带颜色条)
   ========================================= */

/* 普通 Note (蓝色系) */
*[class~="topic/note"] {
    background-color: #f0f9ff !important;
    border-left: 5px solid #0ea5e9 !important; /* Sky Blue */
    padding: 12px 16px !important;
    margin: 16px 0 !important;
    color: #0c4a6e !important;
}

/* Danger / Warning (红色系) */
*[class~="topic/note"][type="danger"],
*[class~="topic/note"][type="warning"] {
    background-color: #fef2f2 !important;
    border-left: 5px solid #ef4444 !important; /* Red */
    color: #7f1d1d !important;
}

/* Note 里的图标对齐优化（如果 Oxygen 自动生成了 SVG 图标） */
*[class~="topic/note"] > * {
    margin-top: 0;
    margin-bottom: 0;
}

/* ============================================================
   Force Dark Codeblock - The "Nuclear" Option (终极核武版)
   ============================================================ */

/* 策略 1: 直接覆盖 Oxygen 的全局 CSS 变量 (最优雅的方法) */
:root {
    --wh-pre-bg: #1e1e1e !important;    /* 背景改黑 */
    --wh-pre-color: #d4d4d4 !important; /* 文字改灰白 */
}

/* 策略 2: 暴力覆盖所有可能的元素组合 (pre, code, 以及带有样式的 div) */
pre, 
code,
*[class~="topic/codeblock"],
.pre, 
.codeblock {
    background-color: #1e1e1e !important;
    color: #d4d4d4 !important;
    border: none !important;
}

/* 策略 3: 专门针对 PrismJS 高亮库 (如果你的 WebHelp 启用了语法高亮) */
/* 这一步是为了防止高亮插件又把背景刷回白色 */
code[class*="language-"],
pre[class*="language-"] {
    background-color: #1e1e1e !important;
    text-shadow: none !important;
}
```

为什么选择器写得这么怪 `*[class~="topic/cmd"]`？ 因为 DITA 输出的 HTML class 通常长这样：`class="- topic/ph task/cmd "`。 使用 `~=` (包含单词) 是 DITA 样式覆盖的标准写法，比简单的 `.cmd` 更稳健。

### 总结

**. 结构严谨性 (The "Strict" Order)**
- **考点**：Task 的标准顺序是什么？    
- **回答**：`prereq` (准备) $\rightarrow$ `context` (背景) $\rightarrow$ `steps` (步骤) $\rightarrow$ `postreq` (收尾)。**绝对不能乱序**

**2. 安全第一原则 (Safety First)**
- **考点**：Warning/Caution 放在哪里？
- **回答**：必须放在 `<cmd>` (动作) **之前**。
- **价值**：这是工业文档的铁律——先预警，后操作。如果放在后面，用户手快已经操作完了，警告就失效了。
    
**3. 动作 vs. 结果 (Action vs. Result)**
- **考点**：怎么区分 `<cmd>` 和 `<info>`/`<stepresult>`？
- **回答**：`<cmd>` 是用户的**动作**（Click, Run）；`<info>` 是辅助说明；`<stepresult>` 是系统的**反馈**（System shows...）。逻辑必须清晰分离。

**4. 排错能力 (Troubleshooting)**
- **考点**：遇到 XML 报错怎么办？
- **回答**：我看待报错是 **DTD/Schema 的正则约束**。我能读懂 `Unexpected element`，并迅速调整标签位置以符合 Content Model。

**5. 样式解耦 (Separation of Concerns)**
- **考点**：如何修改文档样式？
- **回答**：DITA 是**内容与样式分离**的。我不在 Topic 里硬调格式，而是通过 **CSS** 或 **Transformation Scenarios** 统一控制 WebHelp 和 PDF 的输出，保证品牌一致性。
