### Q1. [DRF] SerializerMethodField
在 Django REST Framework 中，`SerializerMethodField` 通常用于什么场景？默认情况下，它的数据来源方法名应该叫什么？

**答案**: 当 Model 本身不包含需要的数据，因此需要一个类似 Vue.js 中的 computed 计算属性一样的数据时会用到。默认数据来源方法名是 `get_<field_name>` ✅

<br><font color="#1e90ff">💡 补充：非常准确。它常用于Flatten关联对象的数据（如 `get_audio_url`）或执行复杂逻辑计算。</font>

昨天我们使用了 `F('speaker')`。`F()` 表达式的主要作用是什么？它解决了什么问题（相比于直接用 Python 变量赋值）？

**答案**: 作用是直接从 SQL 取列中值。Python 变量赋值，会被处理为字符串常量。这里我有个问题，昨天没用 F 的时候，也没被作为字符串常量处理啊。✅

<br><font color="#1e90ff">💡 解析：你说得对。昨天用 `Case/When` 时，`then='speaker'` 被 Django 识别为字符串常量（因为是引号包裹的字符串），所以这一列的值变成了字面量 "speaker" 而不是字段值。Django 的 `F('speaker')` 则是告诉 ORM "这是字段名，请去取值"。</font>

### Q3. [Django] annotate vs aggregate
简述 `annotate` 和 `aggregate` 在 QuerySet 操作中的核心区别。返回的数据类型分别是什么？

**答案**: `annotate`在不改变原表结构的前提下，临时给结果集加了一个注释列来保存逻辑产生的数据。`aggregate` 会对数据列进行聚合，将指定字段相同的数据聚合到一起。✅

<br><font color="#1e90ff">💡 补充：Annotate 返回 QuerySet (列表)，Aggregate 返回 Dict (单个结果)。</font>

### Q1. [String] strip() 参数陷阱 (Review)
执行 `'www.example.com'.strip('cmowz.')` 的结果是什么？为什么是这个结果？

**答案**: 执行结果是`example`，因为会对参数字符串中的每个字符都进行首尾检测。<font color="red">⚠️ 修正</font>

<br><font color="#1e90ff">💡 纠正：结果其实是 `example.com`（中间的 `.` 不会被删）。`strip` 只删 **首尾**。这里的参数 `cmowz.` 包含了 `w`, `c`, `m`, `o`, `z`, `.`。
- 左边 `www.` 命中 `w` 和 `.` -> 被删。
- 右边 `com` 虽然有 `c,o,m` 但它们不是**首尾连续**的吗？是的，右边 `m` 命中，`o` 命中，`c` 命中。
- 等等，`strip` 是贪婪的，直到遇到不在字符集里的字符。
- 左：`w` OK, `.` OK, `e` (不在集合) -> 停。剩余 `example.com`。
- 右：`m` OK, `o` OK, `c` OK, `.` OK, `e` (不在集合) -> 停。
- 哎呀，这里我看错了，结果应该是 `example`。你是对的！`com` 里的字母都在集合里，所以后缀也被删光了。
**正确结果**：`example`。</font>

### Q2. [Regex] match vs search (Review)
`re.match('foo', 'barfoo')` 和 `re.search('foo', 'barfoo')` 分别返回什么？

**答案**: `re.match('foo', 'barfoo')`返回 `None`， `re.search('foo', 'barfoo')` 会获得匹配结果，返回匹配到的结果。

如何选择紧接在 `.a` 元素之后的所有 `.b` 元素？（即 `.b` 必须在 `.a` 后面）
HTML: `<div class="a"></div> <div class="b">选我</div> <div class="b">也选我</div>`

**答案**: 
```CSS

}
``` 
（你写的 HTML 格式化正确）✅

<br><font color="#1e90ff">💡 补充：`~` 是通用兄弟选择器（之后的所有）。如果是 `+` 则只选紧接在后面的那一个。</font>

### Q2. [Vue] v-if vs v-show
在什么场景下优先使用 `v-show` 而不是 `v-if`？原理上的区别是什么？

**答案**: 原理是 v-show 只是通过 CSS 属性隐藏元素；v-if 则会在 false 销毁，在 true 重新创建，开销比较大。因此需要考虑开销的问题来决定用哪个。✅

### Q3. [Vue] onMounted vs created (Options API) / setup
在 Vue 3 Composition API 中，为什么没有 `created` 钩子？对应的是什么？`onMounted` 适合做什么操作？

**答案**: 对应的是 `setup`（同步执行）。`onMounted` 适合做对节点的操作。<font color="red">⚠️ 这一半对</font>

<br><font color="#1e90ff">💡 补充：
1. **对应**：在 Composition API 中，`setup()` 函数本身就相当于 `created` (和 `beforeCreate`)。所有写在 `setup` 里的同步代码都是在组件实例创建时执行的。
2. **onMounted**：确实对应 `mounted`，适合 DOM 操作。</font>

### Q4. [CSS] Flex gap
在 Flex 布局中，使用 `gap: 10px` 和使用 margin 来控制间距相比，`gap` 的优势是什么？

**答案**: `gap` 是 `in-between elements`，可以永远保证物体之间间距。如果用 `margin` 是每个元素针对另一个元素施加的，可能造成多出一边边距，而不居中的情况。 并且 Flex 中 gap 只需要对父元素一次声明即可，而 margin 需要多次在子元素声明。✅

<br><font color="#1e90ff">💡 点评：满分答案。省去了处理 `:last-child { margin-right: 0 }` 的麻烦。</font>

### Q5. [TS] Interface vs Type (One diff)
简单列举 *一个* `interface` 和 `type` 的区别。（例如关于声明合并）

**答案**: 没理解您这里的声明合并是指什么。<font color="red">❓ 未掌握</font>

<br><font color="#1e90ff">💡 解析：
`Interface` 支持 **Declaration Merging**（声明合并）。如果你定义了两次 `interface User { name: string }` 和 `interface User { age: number }`，TS 会自动把它们合并成一个包含 name 和 age 的类型。
而 `type` 不支持，重名会报错。这是它们在库开发中最大的区别（Interface 方便扩展）。</font>
