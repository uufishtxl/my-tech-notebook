### Q8. [Django] Exists Optimization
How does `queryset.exists()` optimize the generated SQL query compared to `bool(queryset)` or `len(queryset)`?

**答案**: `queryset.exists()`不会传输数据本身，因此开销比较低。操作 `queryset` 需要传输数据，开销大。

> 💡 **解析**：**[x] 回答正确**。`exists()` 在底层 SQL 会被优化为类似 `SELECT 1 FROM table LIMIT 1`，它不在意整行数据内容，只要发现符合条件的记录就会立刻返回 true，极大地减小了 DB 与服务器间的 IO 传输和查询开销。

**答案**: 因为只有可哈希的值才可以作为键。而在 `dataclass` 中传入 `frozen=True`就可以自动为实例添加 `__hash__`属性，让数据不可变，可哈希。

> 💡 **解析**：**[x] 回答正确**。可变对象无法作为 `set` 或 dict `key`，`frozen=True` 会阻止实例被修改，而且会自动为你生成 `__hash__` 方法（基于对象的所有字段），使之成为可哈希的。

## 🌟 今日新知 (New Knowledge)

### 1. Django/Security (ALLOWED_HOSTS 防护机制)
- **概念**：`ALLOWED_HOSTS` 是预防 HTTP Host Header 攻击。当用户发起 HTTP 请求时，客户端是可以伪造 `Host:` 请求头的。
- **危害**：如果在后端直接用 `request.get_host()` 生成邮件链接或者做重定向操作，如果被黑客修改成了伪造域名，那么用户点击密码重置邮件时，就会跑到黑客的网站上（密码重置投毒）。
- **区分**：CORS 防止的是前端跨域资源的滥用行为，是浏览器主导的安全策略；`ALLOWED_HOSTS` 保护的是后端在构造绝对 URL 和防止缓存劫持上的安全。（已加入 Box 1 复习队列）

### 2. Vite/DevOps (Proxy & Localhost 优势)
- **概念**：在进行本地跨域代理（Vite 代理到 Django）时，将 `target` 设置为 `http://localhost:8000` 或 `http://127.0.0.1:8000`，不仅省却了因 LAN IP 频繁发生变动带来的不停修改配置的麻烦，且在安全性上它专门约束在环回网卡（Loopback interface）。
- **价值**：网络请求永远不会触及外部网络设备，不会被嗅探软件（如 Wireshark）捕获。如果你设成局域网 IP，意味着任何与你在同一路由器的设备都能访问到你的开放端口（除非配置防火墙禁止外部连接）。（已加入 Box 2 复习队列）
