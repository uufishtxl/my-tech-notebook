## 🌟 今日新知 (New Knowledge)

### 1. Vue: Global Event Lifecycle (全局事件的内存泄漏)
- **概念**：在通过 `v-if` 或路由切换时，Vue 帮你自动卸载的是“虚拟 DOM”以及它包裹的内部标签事件（如 `<div @click="...">`）。但如果是挂在“整个屋子”（`document` 或 `window`）上的事件，Vue 是无权越俎代庖去删除的。
- **后果**：每次组件重新出现（`onMounted`），它就会给 `window` 绑一根新绳子。如果你离开并回来 10 次，你按一次 `ctrl+enter`，相同的 `handleAskAI` 函数就会瞬间并发执行 10 次。且这些闲置的闭包函数会阻止组件的剩余内存被销毁释放。**必须用 `onUnmounted` 手动解绑 `removeEventListener`**。

### 2. Django: AUTHENTICATION_BACKENDS (认证后端的劫持)
- **概念**：Django 默认的认证系统叫 `ModelBackend`（它通过 `User.objects.get(username=...)` 仅验证用户名）。如果你想支持手机号登录、邮箱登录、GitHub 第三方登录等花式操作。
- **操作**：你必须修改 `settings.py` 的大门守卫者：`AUTHENTICATION_BACKENDS` 列表。
- **原理**：当你发送一个用户名/密码。Django 会从头到尾遍历 `AUTHENTICATION_BACKENDS` 里的类，依次调用它们的 `authenticate()` 方法，遇到一个说匹配的就放行。这就是 `allauth` 能够用邮箱将你登录的底层根基。（已加入 Box 1 复习队列）。

```Python
# settings.py
AUTHENTICATION_BACKENDS = [
    # 守卫 1：Django 原生的用户名检查器（保底用的，比如允许超管用 admin 登录）
    'django.contrib.auth.backends.ModelBackend',
    
    # 守卫 2：你强行塞进去的 allauth 专属邮箱检查器 (真正的拦截接管者)
    'allauth.account.auth_backends.AuthenticationBackend',
]

# 只有上面那道门配好了，下面这些 allauth 自己的规则才会有数据传进来让它执行
ACCOUNT_AUTHENTICATION_METHODS = ['email'] 
ACCOUNT_EMAIL_REQUIRED = True
```
当你配置了上面的列表后，Django 底层的 `authenticate()` 函数其实就是跑了一个极其简单的 `for` 循环（纯逻辑流）：

1. Django 拿到你的邮箱 `admin@example.com` 和密码。
    
2. **第一次循环**：把数据交给守卫 1 (`ModelBackend`)。守卫 1 去查 `username`，发现查不到，返回 `None`。
    
3. **第二次循环**：Django 没有报错，而是继续把数据交给守卫 2 (`allauth Backend`)。
    
4. 守卫 2 接过数据，看到你配了 `ACCOUNT_AUTHENTICATION_METHODS = ['email']`，于是它执行了不同的 SQL： `SELECT * FROM auth_user WHERE email = 'admin@example.com';`
    
5. 查到了！比对密码成功，返回 User 对象。`for` 循环终止，登录成功！
