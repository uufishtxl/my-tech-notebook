### Q1. [Django] update() vs save()
当你对一个 QuerySet 调用 `update(status='active')` 时，模型的 `save()` 方法会被调用吗？定义的 `post_save` 信号会被触发吗？为什么？

**答案**: 不会调用 `save()` 方法和 `post_save`信号。因为，这里会直接执行 SQL 语句，绕过了 Django 的设计。 ✅
> 💡 **补充**：如果确实需要触发信号，必须遍历 QuerySet 逐个调用 `save()`，但这会通过 N 次 SQL 更新，性能较差。权衡：性能 vs 业务逻辑一致性。

### Q3. [DRF] SerializerMethodField
你在 `BlitzCardSerializer` 中使用了 `SerializerMethodField`。如果要自定义该字段的返回值，默认需要定义什么名称的方法？如果想用不同的方法名，应该怎么做？

### Q4. [DRF] Serializer Source
在 `BlitzCardSerializer` 中，为什么 `id = serializers.IntegerField(source='id')` 会引发 Assertion Error？正确的写法是什么？

**答案**: 会的。应该换一个变量名。 **❌ 错误**
> 💡 **解析**：不管是 Serializer 还是 ModelSerializer，如果字段名（左侧 `id`）和模型字段名（右侧隐式 `id`）一致，则**不需要**写 `source='id'`。DRF 认为这是多余的（redundant），所以报错。
> **正确写法**: `id = serializers.IntegerField(read_only=True)` (去掉 `source` 即可)。

### Q5. [API] Idempotency
RESTful API 中，`PUT` 和 `POST` 的主要区别是什么？谁是幂等的（Idempotent）？

**答案**: `PUT` 是幂等的。`PUT` 会更新某一笔数据，`POST` 会创建新的数据。 ✅
> 💡 **补充**：**幂等性**是指：对同一个资源进行一次或多次请求，产生的影响是相同的。`PUT` 无论执行多少次，资源的状态都是最终那个状态。而 `POST` 执行多次可能创建多个资源。

### Q6. [String] strip()
代码 `'www.example.com'.strip('cmowz.')` 的执行结果是什么？请解释 `strip` 的工作原理。

**答案**: 结果是 `example`。工作原理是将作为参数的字符串的每一个都作为检查目标，直至被检查的字符串的首尾都不包含包含于其中的任一字符为止。 ✅
> 💡 **点赞**：解释非常精准！很多人误以为是删除整个子串。

### Q10. [Data Types] List vs Tuple
除了可变性（Mutability），List 和 Tuple 在内存占用上通常谁更小？为什么？

**答案**: Tuple 占用的内存更小。因为 List 需要预留空间。Tuple 不可变，Python 可以按需分配。 ✅
> 💡 **补充**：List 是动态数组，为了支持快速 `append`，通常会 over-allocate（预分配）内存。Tuple 定长，不仅不需要预分配，Python 运行时还会对小元组进行资源缓存重用。

### Q11. [Vue] Lifecycle
Vue 3 的 `setup()` 函数执行时机是在 Options API 的 `created` 之前还是之后？在 `setup()` 中可以使用 `this` 吗？

**答案**: `created`就等同于 `setup()`。不可以。因为这时候还没有建立 vm 实例。 ✅

### Q12. [Vue] :key
在 `v-for` 循环中，为什么不建议使用数组索引（index）作为 `:key`？请描述一种会导致渲染错误的场景。

**答案**: 如果用 index 作为数组索引，当发生位置变化（插入或删除）时，可能因为“就地”更新，引发顺序错误。 ✅
> 💡 **场景举例**：如果在列表头部插入一个新项，所有后续项的 index 都会变。Vue 会认为原来的第一个组件变成了新数据，从而错误地复用了组件状态（如输入框里的文字、选中状态）。

### Q14. [CSS] Stacking Context
设置了 `z-index: 9999` 的元素有时仍然会被覆盖，最常见的原因是什么？（提示：关于它的父容器状态）

### Q15. [Vue] Computed
在 Vue 3 的 `<script setup>` 中，访问一个 `computed` 属性的值需要加 `.value` 吗？在 `<template>` 中呢？

**答案**: 在 script 中需要，在 setup 中不需要。 **⚠️ 笔误？**

## 🌟 今日新知 (New Knowledge)

应你的要求，这里补充两个稍深一点的知识点：

1.  **[Python] Slot 继承陷阱**：
    你虽然知道 `__slots__` 可以省内存，但需注意：如果子类继承父类，子类**不会自动继承**父类的 `__slots__`。
    - 如果子类不定义 `__slots__`，它依然会拥有 `__dict__`，导致内存优化失效。
    - 如果子类定义了 `__slots__`，它的实例只能拥有 父类slots + 子类slots 的属性。

2.  **[DRF] Serializer 的验证顺序**：
    当你调用 `serializer.is_valid()` 时，验证顺序是严格的：
    1.  `Default value` / `Allow null` 等基础检查。
    2.  `validate_<field_name>()` 字段级验证。
    3.  `validate()` 对象级（多字段联合）验证。
    4.  `run_validators()` 模型级验证（如果关联了 Model）。
    *Debug 技巧：如果字段级验证没触发，检查一下是否在第一步（如类型错误）就先挂了。*
