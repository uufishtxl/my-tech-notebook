### Q1. [Prompt Engineering] 针对工具调用的显式路径引导 (Explicit Path Guidance)
在向具有工具调用能力的单智能体或多智能体编写系统提示词时，为什么“显式说明文件/代码甚至环境的路径”是一个重要的防御性策略？它能避免什么样的核心失败场景（Failure Mode）？

**答案**: 因为 LLM 可能会进入“偷懒”模式。显式地提供“操作情景的必要描述和举例”可以避免智能体没有按照期望调用工具。

> 💡 **解析**：**[正确 ✅]** 避免“偷懒”是很真实的情况。更深层来看，在复杂环境（比如嵌套目录）中，最核心的 Failure Mode 是**大模型“自行脑补”了错误的相对路径**（幻觉的发生）。这会导致工具（如写入文件）在错误的目录下生效，甚至因找不到文件引起 Agent 崩溃或陷入死循环反复查错。显式的绝对路径引导可以打破这种路径幻觉。

### Q2. [Vite/DevOps] Proxy & Localhost (绑定环回接口与动态 IP)
在使用 Vite 进行前端开发时，如果我们在 vite.config 里面设置了对 `/api` 的后端代理，但后端启动在 `127.0.0.1:8000`，此时有时会遇到在同一台电脑上访问正常，但在手机（同一局域网）访问测试网页时接口请求超时的现象。请结合 IP 绑定的原理（`0.0.0.0` vs `127.0.0.1` vs `localhost`）简述原因。

**答案**: `127.0.0.1` 和 `localhost` 都是限制本机访问，这意味着局域网内其他设备无法访问本机服务，但是这样做安全性更高。如果在安全的家庭环境中，当前后端服务启动了 `0.0.0.0`，就意味着连接到同一路由设备的网络设备都可以访问该服务。

> 💡 **解析**：**[正确 ✅]** 满分回答。`127.0.0.1` 绑定的是本地回环接口（Loopback网卡），数据包根本不经过物理网卡，因此局域网内的其它设备无法访问。而 `0.0.0.0` 意味着监听当前机器上所有可用的网络接口（包括分配给物理网卡的局域网 IP），所以手机才能通过局域网 IP 成功发起请求。

### Q3. [Django/Models] null=True vs blank=True 在字符串字段上的规范
在 Django 的 Models 中（如 CharField, TextField），官方文档强烈建议对于字符串类型的字段**不要**同时设置 `null=True, blank=True`。请解释为什么不推荐在字符串上使用 `null=True`（即区分空字符串和 NULL 的问题所在），并说明标准的空值处理写法是什么？

**答案**: 因为如果在字符串上设置了 `null=True`，如果要判断是不是没有有效的字符串，需要完成 `is None` 和 `== ''` 双重处理。完全可以规避这个问题。

> 💡 **解析**：**[正确 ✅]** 非常对！核心痛点就在于“双重空值状态（Two possible values for no data）”。如果放任这两种状态共存，查询和验证时就容易出 Bug。标准的做法是只使用 `blank=True, default=''`，让数据库和业务逻辑里的“空”统一由空字符串 `""` 来表达。

### Q4. [Database] 事务隔离级别 (RU->RC->RR->S) 
(Box 2) 简述数据库事务的四种常见隔离级别：Read Uncommitted, Read Committed, Repeatable Read, Serializable。并特别说明 MySQL (InnoDB) 的默认级别是哪一个，它主要解决了哪种并发问题（脏读、不可重复读、幻读中的哪一个）？

**答案**: 如下：
- RU - 可以读取其他人未 `Commit` 的数据更新，因此这是脏读，读了别人的东西。
- RC - 一次事务中每次 SQL 查询都会进行快照，因此可能在一次事务中读取到同一个数据不一样的状态，因为这是”不可重复读“，一重复就对不上了。
- RR - 一次事务只进行一次快照，因此单次事务里所有的 SQL 查询到的数据状态都是一致的。因此，这是幻读，比如事务是改10个部门人员的数据，结果等事务完成，你发现部门有11个人了，活见鬼了，因此是”幻读“。
- Serializable - 这会直接导致“写”的通道暂时对外关闭，而只允许当前连接进行“写入数据”。因此可以解决 RR 幻读的问题。当我连接了DB，其他人就别想将这第11个人塞进部门里。
MySQL 默认级别是 RR，主要解决了“不可重复读”的问题。

> 💡 **解析**：**[正确 ✅]** 逻辑非常清晰！进一步补充：MySQL (InnoDB) 默认的 Repeatable Read，凭借其底层独有的 MVCC 机制（多版本并发控制），配合 Next-Key Locks（间隙锁），在相当大程度上其实也顺带着拦截了很大一部分“幻读”问题，非常强大。

### Q5. [Python/Dictionary] 字典健值检测 (in vs hasattr 的陷阱)
(Box 2) 在 Python 中，我们判断一个字典对象 `data: dict` 中是否包含键名 "title"，应该使用 `"title" in data` 还是 `hasattr(data, "title")`？为什么另外一个写法是彻底错误的？

**答案**: 应该使用 `'title' in data`，因为 `hasattr()`方法只能针对 `Class` 实例来检测是否包含某个属性。字典中，即便有 `title` 键，也会返回 `False`。

> 💡 **解析**：**[正确 ✅]** 完美！字典（Dict）中的数据是以键值对（Key-Value Mapping）存储的，而不是类对象的内部属性（Attribute）。`hasattr()` 去查的是对象内部有没有绑定自带的方法或类属性（例如 `hasattr(data, "keys")` 是 `True`），因此绝对不能拿来查字典里存的数据键。

### Q7. [Vue/Animation] (New Knowledge) 过渡与 z-index 叠放陷阱 (Teleport & Popper)
在给带有弹出层的组件（如 ElementPlus 的 Calendar/Select 下拉菜单）制作背景模糊（backdrop-filter）和淡入淡出组件动画（`<Transition>`）时，为什么原生带入的下拉菜单经常会被隐藏在 Widget 的后面？如何使用 Teleport 机制配合全局样式（含 !important z-index）解决这个深层嵌套的遮挡问题？

**答案**: 昨天的 Code，没有Review 呢。过。

> 💡 **解析**：**[未掌握 / 学习后入库]**
其实原因在于 CSS 的堆叠上下文（Stacking Context）。
当父元素（比如你的 Pomodoro Widget）带有 CSS Transform 或透明度（用于 `<Transition>` 动画），或者带有 `backdrop-filter` 时，**浏览器会自动为这个父元素创建一个隔离的“堆叠上下文”**。这就导致内部的所有子元素（包含原生的弹出菜单），哪怕把 `z-index` 设置成 999999，也绝对无法突破这层隔离，就会悲惨地被其他平级的 UI 元素盖住。
解决这个**深层嵌套遮挡**的最优雅办法，就是使用 Vue 的 `<Teleport to="body">`（ElementPlus 的 Select 中提供了 `:teleported="true"` 属性），这会让弹出层的 DOM 从物理上被扔到 HTML 的最外层 Body 上。配合全局顶级 `z-index`，就能突破一切物理局限，实现真正的悬浮覆盖。

### Q8. [Frontend/Audio] (New Knowledge) Audio API 的浏览器就绪判定 (readyState >= 1)
在进行 HTML5 Audio API 的开发时（例如复习卡片发音功能），如果我们想要精准定位到一个音频的时间点（`audio.currentTime = targetTime`），为什么需要检测 `audio.readyState >= 1`，而不是直接给 src 赋值并立即设置 currentTime？如果不检测可能会导致什么结果？

**答案**: 因为会碰到 audio 没有加载完成，而无法定位到指定的开始位置的情况。这我也还没看呢。

> 💡 **解析**：**[未掌握 / 学习后入库]**
感觉已经抓到核心了！如果直接发号施令 `audio.currentTime = xxx`，但这首歌其实才刚刚连上网络连长度都不知道，此时浏览器去哪儿找那个时间点呢？
于是浏览器会立刻反弹抛出一个无情的 `InvalidStateError` 异常（提示 DOM Exception 状态不对）。
因此，规范的做法是必须等待 `loadedmetadata` 事件回调触发，或者判断 `audio.readyState >= 1`（1 代表 HAVE_METADATA，即浏览器的音轨解码器已经知晓了这首曲子的总长度和音轨信息）。只有在 `readyState >= 1` 的状态下执行时间跳跃，才能百分百成功地重定位。

## 🌟 今日新知 (New Knowledge)

### 1. Vue/动画组件带来的 Stacking Context 陷阱 📦
当你发现无论把 `z-index` 设多大都被盖住时：去查它爸爸！
含有 Transform、Opacity（如 `<Transition>`）、`backdrop-filter` 等属性的父级容器会形成结界。要逃出生天，请使用 `<Teleport>` 飞雷神，将 DOM 传送出原本的组件外壳直接挂到主干上，再做图层排序。

### 2. Audio 对象的 `readyState` 机制 🎵
给 audio 赋 `src` 只代表命令它开始吃东西，在它没有嚼完一口咽下去告诉你是什么滋味前（`readyState >= 1` / Metadata 获取完毕），不要问它关于里面任何具体位置的事情（`currentTime` 跳转），否则它会吐给你一个清清脆脆的报错（`InvalidStateError`）抛出。我们一般通过 `onLoadedMetadata` 事件或者判定大于等于 1 来优雅地接听“准备完毕”的热线。
