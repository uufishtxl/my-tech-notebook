## Box 1 (Daily)

### Q1. [Vue] Reactivity Destructuring
在 Vue 3 (< 3.5) 中，直接解构 `const { count } = props` 会导致什么问题？Vue 3.5+ 引入了什么新语法糖解决这个问题？

**用户答案**: 这样如果 props 更新，count 并不会具备活性，仍然保持为解构时的值。Vue 3.5 引入了什么不清楚。

> 💡 **解析**：**部分正确**。
> 1. Vue 3 (< 3.5) 确实会丢失响应性。
> 2. **Vue 3.5+** 默认开启了 **Reactive Props Destructure**。编译器会自动将解构后的变量 `count` 映射回 `props.count`，从而保持响应性，无需再用 `toRefs`。

使用“分数索引”生成排序值时，如果在 `order=100` 和 `order=200` 之间插入新项，通常可以设为多少？如果反复在同一位置插入，会导致什么潜在风险（如精度问题）？

### Q6. [Django] N+1 Problem

**用户答案**: ...造成 SQL 开销成本...外键关联查询，使用 `select_related`。

### Q7. [Vue] Ref vs Reactive
当我们需要重新给一个响应式对象赋值时...应该选用 `ref` 还是 `reactive`？为什么 `reactive` 不能直接解包赋值？

**用户答案**: 应用选用 `ref`。因为...解包赋值后，取到的是死的东西...

> ✅ **正确**。`reactive` 是 Proxy，直接替换变量会断开与 Proxy 的连接。`ref.value` 是属性，可以随意替换。

### Q8. [Django/SQL] Inner Join vs Left Join
如果在 Django 中查询 `User.objects.select_related('profile')`，如果某个 User **没有** Profile，默认使用的是 Inner Join 还是 Left Join？

**用户答案**: 会用 Inner Join。不会出现的结果集中。

> 💡 **解析**：**错误**。
> Django `select_related` 对可空外键（Nullable FK）使用 **LEFT OUTER JOIN**。
> `User` 反向关联 `Profile` (OneToOne) 是**可空的**（用户不一定有 Profile）。
> 因此会使用 LEFT JOIN，该用户**会出现在结果集中**，只是 `user.profile` 字段为 None。
> (如果用 Inner Join，没资料的用户就“消失”了，这通常是 Bug)。

### Q9. [Python] Dict Update vs Merge
`d1.update` vs `d1 | d2` 区别？

**用户答案**: A 会执行就地更新... B 不会执行就地更新，而是会返回一个新的对象...

> ✅ **正确**。Update 是 In-place (Mutation)，Merge (`|`) 是 Immutable (New Object)。
