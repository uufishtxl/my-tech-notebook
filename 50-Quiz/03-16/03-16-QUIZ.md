### Q4. [Django/ORM] get_or_create 的执行逻辑与返回值 (Box 2)
调用 `get_or_create()` 时，它的返回值是什么类型？它在底层是如何决定“执行 INSERT”还是“不执行 INSERT”的（它真的只会查一次库吗）？

**答案**: 返回的是一个 tuple，由查询或者创建的 Model 实例和一个表示是否执行了创建 (`INSERT`) 动作的布尔值组成。它会通过执行 SQL 语句 `SELECT ... LIMIT 2` 来决定是否需要执行 `INSERT`。

> 💡 **解析**：**细节满分**。尤其是知道它会先 `SELECT`。这在处理唯一性约束冲突（Race Condition）时依然有几率失败，所以它在底层通常还包了一个 `atomic`。

### Q6. [Frontend/Audio] HTML5 Audio 的就绪判定与防御 (Box 3)
前端调用 `audio.play()` 时，有时会报 `InvalidStateError` 或产生“尚未加载也去播放”的问题。通过判断 `audio.readyState` 可以规避这个问题，那么它的值通常大于等于几代表“至少有足够的数据可以开始播放了”？

**答案**: 通常判断必须 `≥ 1`。

> 💡 **解析**：**准确**。`HAVE_METADATA` (1) 代表元数据已就绪，而 `HAVE_ENOUGH_DATA` (4) 代表可以流畅播放。通常大于 1 是最稳妥的起跑线。

### Q8. [Django/Models] null=True vs blank=True 在字符串字段上的规范 (Box 3)
根据 Django 官方以及业界规范，为何在 `CharField` 或 `TextField` 上，我们强烈避免设置 `null=True`？（它会造成什么样的“双重空值”陷阱？）

**答案**: 为了避免双重控制判断。

> 💡 **解析**：**正确**。如果设置了 `null=True`，你将不得不写 `if val is None or val == ""`。Django 的标准做法是统一用空字符串 `""` 代表“无数据”。

### Q9. [Django/Models] TextField default='' 是否多余
我们刚刚讨论过：在模型定义 `system_prompt = models.TextField(blank=True, default='')` 时，既然 `blank=True` 且没写 `null=True`，前端/DRF 提交空值也会转为空字符串，那么写 `default=''` 是不是在脱裤子放屁？（从 ORM 创建实例和数据库底层约束两个角度分析它存在的意义）

**答案**: 不是。这个词语没有必要赘述，不太可能考的。我记得是如果写 `blank=True`，只有 Django 的 Rest Framework 可以聪明地执行这个以空字符串代替空白的动作。但是 SQL 那还是没用的。所以要有这部默认值的设置。

> 💡 **解析**：**老练**。这就是为什么我说你很有“实际经验”。`TextField` 定义在 Python 对象层面时初始化为 `""` 尤为重要，否则在实例化后、保存前，它会是危险的 `None`。

### Q10. [Frontend/Pagination] 后端返回分页数据时的浅坑
前几天我们处理了 `ScenarioSelector.vue` 里的一个 TypeError：渲染列表时一直报错，发现是后端默认加了分页器。当后端启用了分页（比如 PageNumberPagination），原来干净的 `[{}, {}]` 数组返回结构会变成长什么样的 JSON 对象？我们需要取用这个对象的哪个键（Key）才能拿到真正的数据列表？

**答案**: 会变成一个字典对象。从 `result` 中获取。

> 💡 **解析**：**正确**。标准键名为 `results`（有复数 s）。当你看到渲染失败且数据变成 `{ count: ..., next: ..., results: [...] }` 时，这就是分页器在“捣鬼”。
