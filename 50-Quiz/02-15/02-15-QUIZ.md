### Q5. [Vue] defineProps Generics
- **你的回答**: 使用 `defineProps`。在 `<>`中传入泛型。
- **点评**: ⚠️ **不完整**。
- **解析**: 仅仅在 `defineProps<T>` 只能定义 Props 的类型。如果你想让 **组件本身** 变成泛型的（即组件接收一个类型参数 `T`，并在 Props 中使用它），你需要在 `<script setup>` 标签上添加 `generic` 属性。
  ```vue
  <script setup lang="ts" generic="T">
  defineProps<{
    items: T[]
    selected: T
  }>()
  </script>
  ```
  这样在使用组件时，Vue 才能推断出 `T` 的类型。

### Q12. [LangGraph] Tool Node Loop (New)
- **你的回答**: 为了让 LLM 从 tools 中找到合适的 tool？我还没看这段代码。
- **点评**: 🆕 **新知识点**。
- **解析**: 这是 **ReAct (Reason + Act)** 模式的核心。
  1. **Reason**: Agent (ScriptEditor) 思考，决定调用工具。
  2. **Act**: 执行工具 (Tools Node)。
  3. **Observe (关键)**: 工具的输出（Result）**必须**返回给 Agent。
  4. **Loop**: Agent 收到工具结果后，再次思考（Next Step），决定是继续调用下一个工具，还是输出最终回答。
  没有这个 Loop，Agent 调用完工具后流程就结束了，无法根据工具结果生成最终回复。

## 🌟 今日新知 (New Knowledge)

### 1. Vue 3 Generic Components (`script generic`)
在构建通用组件（如 `DataList<T>`, `SelectOption<T>`）时，单纯的 TS 泛型无法传递给组件模板。
Vue 3.3+ 引入了 `generic` 属性：
```vue
<script setup lang="ts" generic="T extends { id: number }, U">
import { type PropType } from 'vue'

defineProps<{
  data: T[]
  callback: (item: T) => U
}>()
</script>
```
这使得父组件在使用该组件时，能够获得类型推导（比如 `item` 的属性会有自动补全）。

### 2. LangGraph ReAct Loop Pattern
在 LangGraph 中实现 Agent 的标准模式：
```python
# graph.py

# 1. Edge: Editor -> Tools (条件边)
# 如果 LLM 生成了 tool_calls，这步负责路由到 ToolNode 执行
graph.add_conditional_edges("script_editor", should_continue_tools)

# 2. Edge: Tools -> Editor (回环边)
# ToolNode 执行完后，必须把结果（ToolMessage）传回给 Editor
# 这样 Editor 才能看到执行结果，进行下一步推理
graph.add_edge("tools", "script_editor")
```
**为什么必须回环？**
- LLM 是无状态的 (Stateless between checks)。
- **Step 1**: User: "Fix line 5" -> Editor: "Call `get_line(5)`" -> Stop.
- **Step 2**: Tool executes `get_line` -> Returns "Line 5 content: 'Hello'".
- **Step 3 (Loop)**: Editor sees "Line 5 content: 'Hello'" -> Decides: "Call `edit_line(5, 'Hi')`".
如果没有回环，Step 3 永远不会发生。
