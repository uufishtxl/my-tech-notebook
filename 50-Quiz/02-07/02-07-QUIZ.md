### Q3. [Pending] API Content-Type: Multipart
在 HTTP 请求中，什么情况下必须使用 `Content-Type: multipart/form-data`？它与 `application/json` 在请求体结构上最大的区别是什么（关键词：boundary）？

**答案**: 传输二进制文件的时候。`application/json`传输的是纯文本。`multipart/form-data`会根据 `boundary` 将二进制文件进行分割后传输，比转base64更有效率。
<br><font color="green">✅ 正确</font>

### Q4. [Review] Django ORM: `select_related` vs `prefetch_related`
在昨天的 Blitz Camp 开发中，我们使用了 `ScriptLine.objects.filter(...).select_related('slice')`。

`OneToOne` 肯定用 `select_related`
`ForeignKey` 得看实际情况吧
`Many`
<br><font color="#1e90ff">💡 补充：对于 ForeignKey (即 Many-to-One 的 "One" 端)，我们也使用 `select_related`。例如 `ScriptLine` 有 `chunk` (FK)，查 line 时顺便查 chunk，用 `select_related('chunk')`。</font>

### Q1. [Pending] Vue `v-for` Key
为什么在 `v-for` 中必须使用 `:key`？如果不加或使用 `index` 作为 key，在列表顺序发生变化（如 Insert/Delete）时，会导致什么潜在 Bug？（从 VDOM Diff 角度解释）

**答案**: 因为如果不加 key 的话，会进行就地更新。如果不加，或使用 `index` 作为 `key`，在列表顺序变化时，可能会造成顺序混乱，不符合期望。而如果用数据本身唯一 ID 作为 key，VDOM Diff 会进行比较，对比没有发生变化的数据不会产生开销来重新渲染。
<br><font color="green">✅ 正确。核心是 diff 时若无 key，复用 DOM 可能导致内部状态（如 input 内容）残留错位。</font>
