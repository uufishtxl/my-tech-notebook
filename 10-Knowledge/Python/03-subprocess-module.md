# `subprocess`

使用 `subprocess.run` 执行外部命令，并通过 `check=True` 和 `capture_output=True` 进行错误捕获和输出管理。

`subprocess`的特点是：

* 同步阻塞：当 Python 代码执行到 `subprocess.run(...)`时，它会暂停下来，一直等待 `ffmpeg`这个外部命令执行完毕，然后才会继续往下走。

因此存在局限性，只适用于几秒内就能完成、相对较快的任务。如果任务时间较长，需要使用异步任务队列方案（比如 `Celery`）。

Celery 的工作模式就像一个“任务外包”系统：

- **定义任务**: 把耗时的操作（比如视频转码）定义成一个 Celery “任务”。
- **派发任务**: 当 API 请求进来时，Django 视图不直接执行这个耗时任务。它只是快速地向一个“任务中心”（叫做消息队列，比如 RabbitMQ 或 Redis）发一个消息，说：“嘿，这里有个视频要转码，参数是 XXX”。这个过程非常快，几乎是瞬间完成。
- **立即响应**: Django视图派发完任务后，就可以立即返回一个响应给用户，比如` 202 Accepted`，告诉用户“我们已经收到你的请求，正在后台处理”。用户的网页不会卡住。
- **后台工人执行**: 你会在服务器上单独运行一个或多个“Celery工人”进程。这些“工人”一直在监听“任务中心”。当它们看到有新务 时，就会把它领过来，然后在后台独立地、异步地执行耗时的转码操作。
