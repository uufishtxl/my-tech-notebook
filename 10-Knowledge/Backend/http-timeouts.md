# HTTP Timeouts: Connection vs Read

## 核心区别

### 1. Connection Timeout (连接超时)
- **阶段**：**拨号阶段**。客户端试图与服务器建立 TCP 连接（握手）。
- **含义**：在指定时间内，无法与服务器建立连接。
- **常见原因**：
  - 服务器关机或服务未启动。
  - 防火墙拦截。
  - 网络不通（断网）。
  - DNS 解析失败。
- **比喻**：你打朋友电话，响了半天没人接，或者直接提示“您拨打的用户已关机”。

### 2. Read Timeout (读取超时)
- **阶段**：**通话阶段**。连接已经建立成功，客户端发送了请求，正在等待服务器返回数据。
- **含义**：在指定时间内，服务器没有吐出任何数据（或者两个数据包之间的间隔超过了时间）。
- **常见原因**：
  - **后端处理太慢**：比如 AI 正在生成长文本，或者 SQL 查询太复杂。
  - 死锁：服务器卡死了。
  - 网络拥塞：数据包传输极慢。
- **比喻**：电话打通了，你问了一个问题，对方一直在“呃……”思考，超过 60 秒都没给你答案。

## 在项目中的应用 (Axios)

我们之前的 Bug 就是因为 **Read Timeout** 设得太短。

```typescript
// axios.ts
const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  // 这里的 timeout 主要是 Read Timeout（虽然 Axios 统称为 timeout，
  // 但对于已经连上的请求，它控制的是等待响应的时间）
  timeout: 60000, 
});
```

对于 AI 分析（Sound Script, Dictionary），因为 Gemini 思考和生成需要时间（可能超过 30秒），所以我们必须增加这个值，否则前端会以为服务器挂了而主动断开连接。
