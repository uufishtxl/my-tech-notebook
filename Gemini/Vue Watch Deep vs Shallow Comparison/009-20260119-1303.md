## Q

不懂  DOM Range 对象 以及 range.commonAncestorContainer

resetSelection() 关闭之前的菜单？

## A

没问题，这几个概念是前端处理“富文本”或“选区”时最底层的概念。我们拆开来讲，用最通俗的例子。

### 1\. DOM Range 对象（范围）

想象你在看一本书，你拿了一支**荧光笔**，从某一页的第三行划到了第五行。 这个\*\*“被划出的区域”\*\*，在浏览器里就叫 **Range**。

*   **Selection（选区）**：代表用户当前的选择状态（光标在哪，有没有选中东西）。
    
*   **Range（范围）**：是 Selection 里面的核心数据。它描述了：
    
    *   **起点**在哪（在这个 `<p>` 的第几个字开始）。
        
    *   **终点**在哪（在那张 `<img>` 后面结束）。
        

**Range 最难理解的地方在于：它可以跨越标签。** 比如HTML是这样的：

```
<p>我爱 <b>编程</b> 还有咖啡</p>

```

如果你用鼠标选中了“**编程 还有**”这四个字。 你的 **Range** 其实是：

*   **起点**：在 `<b>` 标签里的文本节点内。
    
*   **终点**：在 `<b>` 后面那个文本节点（" 还有咖啡"）的第3个字位置。
    

* * *

### 2\. range.commonAncestorContainer（公共祖先容器）

这个名字听起来很长，其实意思就是：**“能同时包住起点和终点的最小那个父元素”。**

我们用一个“家族辈分”的例子来看。

假设 HTML 结构是这样的（一棵树）：

```
<div id="文章区域"> (爷爷)
    <p id="段落1"> (爸爸)
        我是 <span id="span1">前</span> 半句，
        <span id="span2">后</span> 半句。
    </p>
</div>

```

#### 情况 A：你只选中了“前”字

*   起点：在 `span1` 里。
    
*   终点：在 `span1` 里。
    
*   **commonAncestorContainer**：就是 `span1` 自己（或者是它里面的文本节点）。
    
    *   _解释：在这个小范围内就搞定了。_
        

#### 情况 B：你选中了“前半句，后半句”

*   起点：在 `span1` 里。
    
*   终点：在 `span2` 里。
    
*   **commonAncestorContainer**：是 `<p id="段落1">`。
    
    *   _解释：`span1` 和 `span2` 是兄弟，包住它们俩的最小长辈就是 `<p>`。_
        

#### 你的代码为什么要查这个？

```
textDisplayRef.value.contains(range.commonAncestorContainer)

```

这就好比你在问：**“刚才用户划词选中的这一坨东西，不管它是跨了多少个标签，它的‘总管家’（祖先）是不是属于我的组件（`textDisplayRef`）？”**

*   如果 **是**：说明用户是在你的文本显示区里选的字，那就弹出菜单。
    
*   如果 **不是**：说明用户可能是在页面底部的 Footer 或者侧边栏选的字，这时候如果不加判断，菜单也会弹出来，那就乱套了。

### 3\. resetSelection() 是关闭菜单吗？

**是的，完全正确。**

在你的逻辑里，`resetSelection()` 通常起“**清场**”的作用。

当程序走到 `else` 或者检测失败（比如用户点到了外面，或者选中的内容不合法）时，你需要做两件事：

1.  **数据层**：把存起来的“选中文字”、“坐标信息”清空。
    
2.  **视觉层**：把那个悬浮的高亮/笔记**图标（菜单）隐藏掉**。
    

这就好比用户在别的地方点了一下鼠标，之前弹出的“复制/引用”小气泡就应该自动消失。

**总结一下：**

*   **Range**：你用荧光笔划的那一道痕迹。
    
*   **commonAncestorContainer**：能把这道痕迹完全包进去的最小那个框框。
    
*   **resetSelection**：没事了，把弹出的东西收起来吧。
