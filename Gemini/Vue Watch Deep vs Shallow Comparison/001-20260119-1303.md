## Q

watch(() => props.highlight, (newHighlight) => {

  editableHighlight.value = { ...newHighlight }

}, { deep: true, immediate: true })




deep: true 是监控 newHighlight 中嵌套的对象（数组）的变化？

## A

简单来说：**是的。**

更准确地说，`deep: true` 是为了告诉 Vue：**即使对象本身的引用（Reference/内存地址）没有变，只是里面的属性值变了，也要触发回调。**

以下是详细的机制解释：

### 1\. 为什么要加 `deep: true`？

你监听的数据源是一个 **Getter 函数**： `() => props.highlight`。

*   **如果不加 `deep: true`：** Vue 默认只会检查函数的返回值是否发生了**引用变化**（即 `oldValue !== newValue`）。
    
    *   只有当你直接把 `props.highlight` 赋值为一个**全新的对象**时（例如父组件执行了 `highlight.value = { id: 2 }`），回调才会触发。
        
    *   如果你只是修改了对象内部的值（例如 `props.highlight.color = 'red'`），Vue 会认为对象还是那个对象（引用没变），**不会**触发回调。
        
*   **加了 `deep: true`：** Vue 会强制遍历 `newHighlight` 对象内部的所有层级属性。
    
    *   无论是 `props.highlight` 换了个新对象，还是 `props.highlight.color` 这种内部属性变了，回调**都会**触发。

### 3\. 代码逻辑补充

```
watch(() => props.highlight, (newHighlight) => {
  // 注意：这里使用了结构 ({...}) 进行浅拷贝
  editableHighlight.value = { ...newHighlight }
}, { deep: true, immediate: true })

```

*   **`immediate: true`**: 组件初始化时，立刻执行一次回调。这通常用于把 `props` 的初始值同步给本地的 `editableHighlight`。
    
*   **`{ ...newHighlight }`**: 这是一种常见的模式。你把 `props`（通常是只读的）复制了一份给本地状态 `editableHighlight`，这样你在当前组件修改 `editableHighlight` 时，不会直接报错（避免直接修改 props），也不会立刻污染父组件的数据。
    

### 总结

这行代码的意图非常明确：**“无论 `props.highlight` 是换了个新对象，还是里面的字段变了，都立刻把它的最新状态同步拷贝给 `editableHighlight`。”**
