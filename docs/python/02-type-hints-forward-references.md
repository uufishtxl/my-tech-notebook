# Python > 类型提示：前向引用（Forward References）

## 为什么使用前向引用

* 避免“先有鸡还是先有蛋”的问题：
	* Python 解释器是从上到下读取代码文件的。当它读到某个方法返回某个自定义类时，它需要知道这个自定义类是什么。
	* 在某些复杂的情况下（比如循环导入：A 文件 导入 B，B 文件又导入 A），或者当类型定义在引用的下方时，那么这个自定义类可能当时还是未知的，直接使用会导致 `NameError`。
* 因此，这时候需要使用**字符串**作为“占位符”。通过将这个类型携程要给字符串，比如`'AudioSlice'`，等于在告诉 Python 和类型检查工具：这个函数的返回值是一个叫做 `AudioSlice`的类型。你现在不用急着去找它是什么，先把它当成一个字符串记下来。等所有文件都加载完毕后，你再回过头来解析它到底指向哪个类。
* 这就延迟了类型提示的“求值”时机，从而完美地解决了上面提到的 `NameError` 或循环导入的问题。

这个知识点和模型（Model）有关系吗？

- 这个技巧是 Python 类型提示系统的一个通用功能，不是 Django 模型特有的。
- 但是，它在 Django 项目中非常常用，因为 Django 项目中模型经常使用复杂的外键关联（`ForeignKey`，`ManyToManyField`），很容易在不同的 `models.py`文件或 `services.py`与 `models.py`之间造成循环导入。
- 另外一个模型的方法可能需要返回它自身的实例，这时候也需要使用前向引用。

在 Python 3.7+ 版本中，可以通过在文件顶部添加 `from __future__ import annotations`，来让这个过程变得更优雅。这行代码会自动将文件内所有的类型提示都当做“前向引用”来处理，这样就可以直接写类，而不需要加引号了。
