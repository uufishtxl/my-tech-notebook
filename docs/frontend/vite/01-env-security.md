# Vite 环境变量 (`.env`) 与安全架构

## 1. 核心概念：Vite 如何处理 `.env`

Vite 会在构建时，自动从 `frontend/.env` 文件中读取环境变量。

- **`VITE_` 前缀 (VITE_ prefixed):**
    - **原理：** 只有以 `VITE_` 开头的变量，才会被**暴露**给前端 JavaScript 代码。
    - **访问：** 在代码中通过 `import.meta.env.VITE_MY_VAR` 访问。
    - **警告：** Vite 的工作原理是“查找-替换”。它会把这个变量的值**直接编译**进**公开**的 JavaScript 文件里。
    - **结论：** 绝对不能用于存放任何**私密 Key**。

- **无 `VITE_` 前缀 (Non-prefixed):**
    - **原理：** `Vite` 会读取它们（用于 `Vite` 自身的 Node.js 配置），但**绝不会**把它们暴露给 `import.meta.env`。
    - **结论：** 这是安全的，但也导致前端代码无法访问。

## 2. 架构最佳实践 / 面试场景

这个 Q&A 格式非常好，我们保留它：

> 👨 **面试官：** 我有一个私密的 `DEEPSEEK_API_KEY`，我该如何让我的 Vue 组件使用它？

> 👩 **你 (满分答案)：** 这是一个陷阱问题。**Vue 组件（前端）永远、绝对不能‘使用’或‘知道’这个私密的 Key。**
>
> 1.  **安全架构：** 在一个全栈项目中，这个私密的 `DEEPSEEK_API_KEY` 必须**只**存在于**`backend/.env`** 文件中，由**后端服务器**（Django）在*运行时*安全地读取。
>
> 2.  **前端的角色：** Vue（前端）的角色是调用我们**自己**的 Django API（比如 `/api/v1/lookup/`）。
>
> 3.  **后端的角色：** 我们的 Django `views.py`（后端）在收到这个请求后，**由它**去读取 `backend/.env`，拿到 Key，**由后端**去安全地调用 Deepseek API，然后把“安全的结果”（AI 的回答）返回给前端。
>
> 4.  **`VITE_` 的用途：** `frontend/.env` 文件**只**能存放**非私密**的、以 `VITE_` 开头的配置（比如 `VITE_API_BASE_URL`），因为这些值会被**编译**进公开发布的前端代码里。
