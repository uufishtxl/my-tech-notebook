### [Regex]

> 我们在修复脚本解析时用了 `*?` (例如 `[A-Za-z\s]*?`)。 正则表达式中 `*` 和 `*?` 的区别是什么？

| **符号**  | **意思是... (Quantifier)** | **贪婪性 (Greediness)** |
| ------- | ----------------------- | -------------------- |
| **`*`** | **0次 或 无限次**            | 默认是**贪婪**的 (能吃多少吃多少) |
| **`+`** | **1次 或 无限次**            | 默认是**贪婪**的 (能吃多少吃多少) |
| **`?`** | **0次 或 1次**             | 默认是**贪婪**的 (优先吃1次)   |
如果直接使用 `?`，正则会认为你限制了长度，只能有 0 个或 1 个，而不是限制贪婪程度。
正则：`<.+?>` (假设你想问为什么不写成 `<.?>`)
如果你写 `<.?>`，意思是：
1. `<`
2. `.` (任意字符) **出现 0 次或 1 次** (注意：这里限制了长度！)
3. `>`

正则：`<.*?>`
这里有两个部分：
1. `*` 说：中间可以有 **无限个字符** (长度不限，解决了 `div` 长度为 3 的问题)。
2. `?` 说：**但是！** 虽然可以无限，请**尽可能少匹配**，遇到第一个 `>` 就停下来。
**结果**：成功匹配 `<div>`。

### 总结一张表

|**写法**|**逻辑翻译**|**长度限制**|**贪婪模式**|
|---|---|---|---|
|`.`|任意字符|固定 1 个|-|
|`.?`|0个或1个|**Max 1**|贪婪 (优先匹配1个)|
|`.*`|0到无限个|**无限**|**贪婪** (一口气吃到字符串结尾，再往回吐)|
|`.*?`|0到无限个|**无限**|**非贪婪** (吃一个看一眼，满足了就停)|

- `re.match`强制要求模式串从字符串的第一个字符就开始匹配。
- `re.search` 扫描整个字符串

前端必须将 Content-Type 设置为 **`multipart/form-data`**，因为这是传输二进制文件的标准格式。

后端 Django (尤其是 DRF) 会使用 `MultiPartParser` 来解析请求，将文件数据放入 `request.FILES` 中。

当然，如果要验证图片合法性或处理图片，Django 的 `ImageField` 底层依赖 **`Pillow`** 库。"

> 前端上传图片时，Content-Type 必须设置为什么？Django 后端用什么组件来解析这种请求？

这里我混淆了两个概念：
* 文件的MIME 类型：`image/jpeg`
* Content-Type: HTTP 请求的 Content Type，比如 `multipart/form-data`

普通的 Content-Type 请求只能发纯文本，比如 `application/json`、`x-www-form-urlencoded`。要上传文件（二进制流），浏览器必须把请求体切成多块 Part，每一块用一个 `boundary` 分界线隔开。

### position 属性

>**问题**：`position: sticky` 的工作原理是什么，它需要什么条件才能生效？


需要设置 `top/bottom`阈值，且父元素不能`overflow: hidden`
**本质原理 (Hybrid Mode)**：
- **未达到阈值时**：表现得像 `position: relative`（占位，随文档流滚动）。
- **达到阈值时**：表现得像 `position: fixed`（固定在视口），**但是**！
- **边界限制**：它的“固定”是有范围的。它**死也出不去父容器（Parent）的范围**。如果父容器滚出了屏幕，它也会被带走。

### 数据库隔离级别

**1. Read Uncommitted (读未提交)**

- **背诵点**：**脏读** (Dirty Read)。
    
- **现象**：别人没 Commit 的数据，你能读到。
    

**2. Read Committed (读已提交)**

- **背诵点**：**不可重复读** (Non-Repeatable Read)。
    
- **现象**：别人 Commit 了，你就能读到。导致你前后两次读的不一样。
    

**3. Repeatable Read (可重复读) [MySQL 默认]**

- **背诵点**：**快照** (Snapshot)。
    
- **现象**：不管别人怎么改，你永远读到你事务开始时的那个值。
    

**4. Serializable (串行化)**

- **背诵点**：**排队** (Queue/Lock)。
    
- **现象**：读写互斥。我在读，你就不能改；我在改，你就不能读。

## 使用 `slots` 的目的 

在 Python 中，每个对象默认都有一个 `__dict__` 字典来存储属性。字典虽然灵活（可以随时加新属性），但非常占内存。

当你使用 `__slots__ = ['x', 'y']` 时：

1. **禁用了 `__dict__`**：Python 不再为每个实例创建字典。
    
2. **紧凑存储**：Python 只会为 `x` 和 `y` 分配固定的内存空间（类似于 C 语言的结构体）。
    
3. **副作用**：你不能再动态给对象添加 `z` 属性了（会报错），只能用 `x` 和 `y`。
    

**面试场景举例：** “如果我们系统里需要创建 **数百万个** 小对象（比如像素点 Point(x, y)），内存不够用了，怎么办？” 👉 **“给类加上 `__slots__`。”**

`slots`：
* 牺牲了动态添加属性的能力
* 牺牲了继承的“省心程度”
* 牺牲了部分高级功能 (如 weakref)

## OOP 中`__str__` 和 `__repr__` 的区别
* `__str__` 是给用户看的；
* `__repr__` 是给程序员看的；
* 如果没有定义 `__str__`，会默认调用 `__repr__`
* 如果同时存在，`print()` 会调用 `__str__`；直接读取变量，比如 `john` 会调用 `__repr__`，或者比如将 `john` 放入列表中 `print([john])`，也会调用 `__repr__` 打印。
